# Node JS

## What is Node.js?

Node.js ek **open-source** aur **cross-platform JavaScript runtime environment** hai jo hume **JavaScript code browser ke bahar run** karne ki facility deta hai.

Pehle JavaScript sirf **client-side** (browser ke andar) use hoti thi, jaise button click, form validation, UI changes, etc.  
Lekin **Node.js ke aane ke baad JavaScript server-side par bhi run hone lagi**, jisse hum backend applications bana sakte hain.

Isse **"JavaScript Everywhere"** concept aaya, jisme:
- **Frontend (client-side)** ke liye bhi JavaScript  
- **Backend (server-side)** ke liye bhi JavaScript  

use hoti hai.  
Is approach se development **simple, fast aur productive** ho jata hai.

---

## Benefits of Node.js

### 🚀 Performance
Node.js **V8 JavaScript engine (Google Chrome ka engine)** use karta hai jo kaafi fast hota hai.  
Iske saath **non-blocking, event-driven I/O model** hota hai, jiski wajah se Node.js especially **I/O-bound tasks** (jaise API calls, database operations, file handling) me bahut efficient hota hai.

### 📈 Scalability
Node.js ek hi time par **hazaaron concurrent users** ko easily handle kar sakta hai bina server ko heavy banaye.  
Iski architecture applications ko **highly scalable** banati hai.

### 🌐 Full-Stack JavaScript
Node.js ke saath **frontend aur backend dono ke liye JavaScript** use hoti hai.  
Isse developer ko baar-baar language switch nahi karni padti, development fast hota hai aur team coordination better hota hai.

### 📦 Large Ecosystem
Node.js ke paas **npm (Node Package Manager)** hota hai jisme **hazaaron ready-made packages** available hote hain.  
Isse developers ko sab kuch scratch se likhne ki zarurat nahi padti aur kaam jaldi hota hai.

### 👥 Strong Community
Node.js ki **global community kaafi badi aur active** hai.  
Agar koi issue aaye to solutions, tutorials aur open-source help easily mil jaati hai.

### ⚡ Real-time Capabilities
Node.js ka event-driven nature **real-time applications** ke liye perfect hai, jaise:
- Chat applications  
- Online games  
- Live collaboration tools  

### 📚 Easy to Learn
Agar aapko pehle se **JavaScript aati hai**, to Node.js seekhna kaafi easy hota hai kyunki learning curve low hota hai.

### 💰 Cost-Effective
Ek hi language stack use hone aur efficient resource usage ki wajah se  
**development aur infrastructure cost dono kam** ho jaati hai.

## How Express.js Works?

Express.js **client aur server ke beech request–response model** par kaam karta hai.

### 🔁 Request – Response Flow (Simple Language)

1. **Client (Browser / App)**  
   User browser ya mobile app se koi request bhejta hai  
   (jaise: page open karna, form submit karna, data mangna).

2. **Request Express.js Server tak jaati hai**  
   Ye request HTTP methods ke through hoti hai:
   - GET
   - POST
   - PUT
   - DELETE

3. **Express.js Request ko Process karta hai**  
   Express:
   - Route check karta hai  
   - Middleware run karta hai  
   - Business logic execute karta hai  
   - Database se data leta ya store karta hai  

4. **Server Response bhejta hai**  
   Process complete hone ke baad Express.js **response** wapas client ko bhej deta hai  
   (HTML, JSON, status code, etc.).

---

## 🗂 CRUD Operations in Express.js

Express.js mostly **CRUD operations** ke liye use hota hai:

| CRUD       | Meaning                      | HTTP Method |
|------------|------------------------------|-------------|
| **Create** | Naya data add karna          | POST        |
| **Read**   | Data fetch karna             | GET         |
| **Update** | Existing data update karna   | PUT         |
| **Delete** | Data delete karna            | DELETE      |

---

## 💡 Short Example (Understanding)

- User ne **form submit** kiya → Request Express server ko gayi  
- Express ne **POST route** handle kiya  
- Data **database me save** hua  
- Server ne **success response** wapas bhej diya  

---

### ✅ Summary
Express.js:
- Request receive karta hai  
- Logic & database ka kaam karta hai  
- Client ko proper response deta hai  

Is simple flow ki wajah se Express.js **fast aur powerful backend framework** mana jata hai.

# 🚦 Basic Routing in Express.js

**Routing** ka matlab hota hai — jab client kisi specific **endpoint (URI)** par request bhejta hai,  
to server uska response kaise dega.  
Express.js me hum different **HTTP methods** (GET, POST, PUT, DELETE, etc.) ke liye  
alagalag routes define kar sakte hain.

---

## 🧠 Common Routing Methods in Express.js

| Method            | Description                                                                   | Example                                                       |
|-------------------|-------------------------------------------------------------------------------|---------------------------------------------------------------|
| **app.get()**     | GET requests handle karta hai (data fetch karne ke liye use hota hai)         | `app.get('/', (req, res) => res.send('GET Request'))`         |
| **app.post()**    | POST requests handle karta hai (data send/save karne ke liye use hota hai)    | `app.post('/', (req, res) => res.send('POST Request'))`       |
| **app.put()**     | PUT requests handle karta hai (existing data update karne ke liye)            | `app.put('/', (req, res) => res.send('PUT Request'))`         |
| **app.delete()**  | DELETE requests handle karta hai (data delete karne ke liye)                  | `app.delete('/', (req, res) => res.send('DELETE Request'))`   |
| **app.all()**     | Sabhi types ke HTTP methods handle karta hai (GET, POST, PUT, DELETE sab)     | `app.all('*', (req, res) => res.send('Handles All Methods'))` |

---

# 🌐 HTTP Request Methods (Hindi + English Notes in Table Format)

HTTP me kai saare **request methods** hote hain jinka use client server se kaise interact karega, ye decide karne ke liye hota hai. Inhe hum **HTTP verbs** bhi bolte hain.

Har method ka apna specific purpose hota hai. Kuch methods **safe**, **idempotent**, aur **cacheable** bhi hote hain.

---

# 📊 HTTP Methods Table (Easy Hinglish Explanation)

| HTTP Method | Purpose                                     | Explanation                                                                         |
|-------------|---------------------------------------------|-------------------------------------------------------------------------------------|
| **GET**     | Resource ko retrieve karna (sirf data lena) | Server se data **mangte** hai. Ye sirf read-only hota hai. Request body nahi hoti.  |
| **HEAD**    | GET jaisa hi, par bina response body ke     | Server se **sirf headers** mangta hai. Body return nahi hoti.                       |
| **POST**    | Naya data submit karna                      | Naya resource create karna ya server state me change lana.                          |
| **PUT**     | Resource ko completely replace karna        | Purane resource ko **poora overwrite** kar deta hai new content se.                 |
| **DELETE**  | Resource ko delete karna                    | Server se kisi resource ko **remove** karta hai.                                    |
| **CONNECT** | Tunnel establish karna                      | Secure HTTPS connections ke liye proxy ke through tunnel banata hai.                |
| **OPTIONS** | Communication options check karna           | Server se ye puchta hai ki is resource par **kaun-kaun se methods allow** hain.     |
| **TRACE**   | Loop-back test perform karna                | Request ko wapas mirror karke network debugging me help karta hai.                  |
| **PATCH**   | Partial update karna                        | Resource me **thoda-thoda change** apply karta hai, poora replace nahi karta.       |

## 💡 Example

```js
const express = require('express');
const app = express();

app.get('/', (req, res) => {
  res.send('GET request received');                         // (Home) Get Request
});

app.get('/about', (req, res) => {                           // (Home/about) Get Request
  res.send('<h1>Hello World</h1>');
});

app.get('/user/:userid/book/:bookid', (req, res) => {       // Pass value through route parameters
  res.send(req.params);
});

app.get('/user/:userid-:bookid', (req, res) => {            // Pass value through route parameters
  res.send(req.params);
});

app.get('/search', (req, res) => {                          // Search query parameters
  res.send(req.query);
});
// localhost:3000/search?name=abhishek&age=20&city=ajmer
```

## HTTP Redirect Codes (Express.js me use hone wale)

Redirect codes tab use hote hain jab server client ko **ek URL se dusre URL par bhejna** chahta hai.

| Code    | Meaning (Hinglish me)                                                                 | Kab Use Hota Hai                                            |
|---------|---------------------------------------------------------------------------------------|-------------------------------------------------------------|
| **301** | **Permanent Redirect** – resource permanently nayi URL par shift ho chuka hai         | Jab page permanently move ho gaya ho (SEO ke liye best)     |
| **302** | **Temporary Redirect** – resource temporary nayi URL par move hua hai                 | Jab kuch time ke liye redirect karna ho                     |
| **303** | **See Other** – POST / PUT ke baad client ko GET request par redirect karta hai       | Form submit ke baad success page par bhejne ke liye         |
| **307** | **Temporary Redirect (Strict)** – 302 jaisa hi hai, lekin **method change nahi hota** | Non-GET requests (POST, PUT) ke liye better                 |
| **308** | **Permanent Redirect (Strict)** – 307 ka permanent version                            | Jab resource permanently move ho aur method same rakhna ho  |

## MVC Pattern (Hinglish me Simple Explanation)

### MVC ka Full Form
**MVC = Model – View – Controller**

MVC ek **design pattern** hai jo code ko clean, organized aur easy-to-manage banata hai.

---

## 1️⃣ MVC Components – Table Format

| Part            | Kaam kya hota hai                                 | Simple Example              |
|-----------------|---------------------------------------------------|-----------------------------|
| **Model**       | Database + Data logic handle karta hai            | MongoDB Schema, User Model  |
| **View**        | User ko jo dikhai deta hai (UI)                   | HTML, EJS, React UI         |
| **Controller**  | Business logic + Model aur View ke beech mediator | create user, update user    |

---

## 2️⃣ Har Part ko Thoda Detail me Samjho

| Component       | Detail Explanation (Hinglish)                                                                                                                 |
|-----------------|-----------------------------------------------------------------------------------------------------------------------------------------------|
| **Model**       | Ye database se related hota hai. Yahi decide karta hai data ka structure kya hoga (Schema) aur DB operations (create, find, update, delete).  |
| **View**        | Ye frontend part hota hai. User ko jo page ya data dikh raha hota hai wo View se aata hai.                                                    |
| **Controller**  | Ye main dimaag hota hai. User se request leta hai, Model se data mangwata hai aur View ko response bhejta hai.                                |

---

## 3️⃣ MVC Workflow (Request ka Flow)

| Step | Flow                                                   |
|------|--------------------------------------------------------|
| 1️⃣   | User browser me URL hit karta hai                      |
| 2️⃣   | Request **Route** ke paas jaati hai                    |
| 3️⃣   | Route request ko **Controller** ko deta hai            |
| 4️⃣   | Controller **Model** se data mangta / save karta hai   |  
| 5️⃣   | Model data return karta hai                            |
| 6️⃣   | Controller response **View** ko bhejta hai             |
| 7️⃣   | View user ko final response dikhata hai                |

👉 Example URL:  
`www.abc.com/user/15`

---

## 4️⃣ MVC ka Real-Life Example

| Real Life | MVC |
|---------|-----|
| Restaurant ka Menu | View |
| Kitchen | Model |
| Waiter | Controller |

Waiter (Controller) order leta hai → Kitchen (Model) me food banta hai → Customer ko serve hota hai (View).

---

## 5️⃣ MVC Pattern ke Benefits – Table Format

| Benefit | Matlab |
|-------|-------|
| Organized Code | Code clean aur structured hota hai |
| Independent Blocks | Model, View, Controller alag-alag kaam karte hain |
| Less Complexity | Badi applications simple lagti hain |
| Easy Maintenance | Bug fix aur update easy hota hai |
| Easy Modification | Ek part change karo, baaki safe |
| Code Reusability | Same code dubara use ho sakta hai |
| Team Collaboration | Frontend & Backend team alag kaam kar sakti hai |
| Platform Independent | Web, Mobile sab me use ho sakta hai |

---

## 6️⃣ Short Summary (Exam / Interview ke liye)

> MVC ek design pattern hai jisme application ko 3 parts me divide kiya jaata hai:  
> **Model (Data), View (UI), Controller (Logic)**  
> Isse code clean, scalable aur maintainable ban jaata hai.

## DotEnv Package (Hinglish me Simple Explanation)

### 🔹 DotEnv kya hota hai?
**dotenv** ek npm package hai jo `.env` file ke variables ko **Node.js app me use karne deta hai**.

Matlab:  
👉 Jo **secret ya config values** hoti hain (DB URL, API key, port), unko code me directly likhne ke bajay `.env` file me rakhte hain.

---

## 📁 `.env` File ka Use – Table Format

| Cheez | Kya store hota hai | Example |
|-----|------------------|--------|
| Database URL | DB connection string | `MONGO_URL=mongodb://localhost:27017/test` |
| API Keys | Third-party services keys | `API_KEY=abcd1234` |
| Port Number | Server ka port | `PORT=5000` |
| Credentials | Username / Password | `DB_PASSWORD=123456` |

---

## ❌ Hardcoding Problem (Galat Tarika)

```js
const password = "123456"; // ❌ insecure
```

## ✔️ Dotenv Solution (Sahi Tarika)
```js
DB_PASSWORD=123456
process.env.DB_PASSWORD
```

## ⚙️ Dotenv kaise use karte hain?

1️⃣	Install dotenv → npm install dotenv
2️⃣	Import karo → require("dotenv").config()
3️⃣	Use karo → process.env.VARIABLE_NAME or existing file me karna ho tab pahle usko import karke .config() karo

## 🧠 DotEnv ke Benefits – Table Format
🔐 Security	Secrets code me visible nahi hote
🔁 Portability	Code change kiye bina values change
📦 Better Management	Saare config ek file me
🚀 Easy Deployment	Local, staging, production alag-alag env

# ExpressJS : What is Middleware ?

Middleware = ek **function** jo **request (req)** aur **response (res)** ke beech me kaam karta hai  
aur decision leta hai ki request aage jayegi ya nahi.

Visitor  --->  Middleware (Conditional Check)  --->  Express JS Server

## Middleware kya kya check karta hai?
- Authenticated User
- Authenticated and Administrator
- Valid Age
- Save Log Information
- Maintenance Mode
- Error Handling

## Example Middleware
```js
app.use((req, res, next) => {
  // Your code.....
  next();
});
```

## Routes
```js
app.get('/about', (req, res) => {});
app.get('/gallery', (req, res) => {});
```

# ExpressJS : Types of Middleware (Table Explanation)

| Middleware Type                   | Kya hota hai                                      | Kab use hota hai                            | Example                                                               |
|-----------------------------------|---------------------------------------------------|---------------------------------------------|-----------------------------------------------------------------------|
| **Application-Level Middleware**  | Puri app ke liye kaam karta hai (sab routes par)  | Logging, authentication, body parsing       | `app.use((req,res,next)=>{ console.log("Request"); next(); })`        |
| **Router-Level Middleware**       | Sirf specific router ya route group ke liye       | `/user`, `/admin` jaise routes ke liye      | `router.use((req,res,next)=>{ next(); })`                             |
| **Error-handling Middleware**     | Errors ko handle karta hai                        | Jab error aaye ya `next(err)` call ho       | `app.use((err,req,res,next)=>{ res.status(500).send(err.message) })`  |
| **Built-in Middleware**           | Express ke saath already aata hai                 | JSON, form data, static files handle karna  | `express.json()`                                                      |
| **Third-Party Middleware**        | External npm packages                             | Security, logging, file upload              | `morgan`, `cors`, `multer`                                            |

---

## 1️⃣ Application-Level Middleware
```js
app.use((req, res, next) => {
  console.log("Request URL:", req.url);
  next();
});
```
➡️ Har request par chalega

## 2️⃣ Router-Level Middleware
```js
const router = express.Router();

router.use((req, res, next) => {
  console.log("User Router Middleware");
  next();
});

app.use('/user', router);
```
➡️ Sirf /user routes par chalega

## 3️⃣ Error-handling Middleware
```js
app.use((err, req, res, next) => {
  res.status(500).json({ error: err.message });
});
```
➡️ 4 parameters hote hain (err, req, res, next)

## 4️⃣ Built-in Middleware
```js
app.use(express.json());              // JSON data
app.use(express.urlencoded({extended:false})); // Form data
app.use(express.static('public'));    // Static files
```

## 5️⃣ Third-Party Middleware
```js
import cors from 'cors';
import morgan from 'morgan';

app.use(cors());
app.use(morgan('dev'));
```

---

## Step-by-Step Explanation (Table Format)

| Step | Code / Concept | Explanation (Hindi + English) |
|-----|---------------|-------------------------------|
| 1️⃣ | `npm install express-validator` | express-validator package install karte hain jo validation rules provide karta hai |
| 2️⃣ | `body, validationResult` | `body()` → request body ke fields validate karne ke liye<br>`validationResult()` → errors collect karne ke liye |
| 3️⃣ | `validationRegistration` | Validation rules ka array jisme hum conditions define karte hain |
| 4️⃣ | `app.post()` | Route par validation middleware apply hota hai |

---

## 1️⃣ Package Install
```bash
npm install express-validator
```
➡️ Ye library Express me form validation ke liye use hoti hai

## 2️⃣ Import express-validator
```js
const { body, validationResult } = require("express-validator");
```
- body() → form ke input fields validate karta hai
- validationResult() → validation ke errors return karta hai

## 3️⃣ Validation Rules Define Karna
```js
var validationRegistration = [
  body('username')
    .notEmpty()
    .withMessage('Username is required'),

  body('password')
    .isLength({ min: 5, max: 10 })
    .withMessage('Password must be between 5 and 10 characters long')
];
```
- 🔍 Samjho:
  - username empty nahi hona chahiye
  - password 5–10 characters ke beech hona chahiye
  - Agar condition fail hoti hai → custom error message aayega

## 4️⃣ Route ke andar Validation Use Karna
```js
app.post('/saveform', validationRegistration, (req, res) => {
  const result = validationResult(req);
  res.send(result);
});
```

## ⚙️ Flow:
- /saveform par request aayi
- `validationRegistration` middleware chala
- `validationResult(req)` errors collect karega
- Errors ko response me send kar diya

# ExpressJS : Form Validation (express-validator)

ExpressJS me **Form Validation** ka use hota hai user ke input ko  
✔️ validate karne (sahi hai ya nahi)  
✔️ sanitize karne (clean & safe banana)  
✔️ custom rules lagane ke liye  

Ye sab kaam **express-validator** library se hota hai.

---

## 1️⃣ Validation Methods (Input Check Karne ke Liye)

| Method                | Use               | Explanation                           |
|-----------------------|-------------------|---------------------------------------|
| `notEmpty()`          | Empty check       | Field empty nahi hona chahiye         |
| `isEmail()`           | Email check       | Valid email format check karta hai    |
| `isLength({min,max})` | Length check      | String ki length min–max ke beech ho  |
| `isNumeric()`         | Number check      | Sirf numbers allow                    |
| `isAlpha()`           | Alphabets only    | Sirf A–Z / a–z                        |
| `isAlphanumeric()`    | Alpha + number    | Letters + numbers allowed             |
| `isURL()`             | URL check         | Valid URL hai ya nahi                 |
| `isDate()`            | Date check        | Valid date format                     |
| `isInt()`             | Integer check     | Sirf integer values                   |
| `isStrongPassword()`  | Strong password   | Strong password rules apply karta hai |
| `isUpperCase()`       | Uppercase         | Value uppercase me honi chahiye       |
| `isLowerCase()`       | Lowercase         | Value lowercase me honi chahiye       |
| `matches(pattern)`    | Regex match       | Custom regex pattern match            |

### Example
```js
body('email').isEmail().withMessage('Invalid email')
```

## 2️⃣ Sanitization Methods (Data Clean Karne ke Liye)

| Method | Use | Explanation |
|------|------|-------------|
| `trim()` | Spaces remove | String ke start aur end ke extra spaces hata deta hai |
| `ltrim()` | Left trim | Sirf left side ke spaces remove karta hai |
| `rtrim()` | Right trim | Sirf right side ke spaces remove karta hai |
| `escape()` | HTML escape | HTML special characters ko escape karta hai (XSS attack se protection) |
| `unescape()` | HTML unescape | Escaped HTML characters ko normal text me convert karta hai |
| `normalizeEmail()` | Email clean | Email ko standard format me convert karta hai |
| `toInt()` | Number convert | String value ko integer me convert karta hai |
| `toFloat()` | Float convert | String value ko float number me convert karta hai |
| `toBoolean()` | Boolean convert | String value ko true / false me convert karta hai |

### Example
```js
body('username').trim().escape()
```
---

## 3️⃣ Custom Validation (Apna Rule Banana)

| Method | Use | Explanation |
|------|------|-------------|
| `custom(validator)` | Custom logic | Apni custom condition likh sakte ho validation ke liye |
| `customSanitizer(sanitizer)` | Custom clean | Apni custom sanitization logic likh sakte ho |

## Custom Validator Example

## 📁 Express.js – File Upload using Multer

### 🔹 Multer kya hai?
**Multer** ek middleware hai jo **multipart/form-data** handle karta hai, mainly **file upload** ke liye use hota hai in **Express.js**.

---

## 🧩 Multer ke Main Parts

### 1️⃣ Storage
Ye decide karta hai:
- file **kahan store hogi**
- file ka **naam kya hoga**

**Options:**
- `destination` → upload folder
- `filename` → file ka custom naam

---

### 2️⃣ Limits
File upload par restrictions lagane ke liye.

**Common limits:**
- `fileSize` → max size (bytes me)
- `files` → max number of files
- `fields`
- `fieldNameSize`

📌 **Size Calculation:**
- 1 KB = 1024 Bytes  
- 1 MB = 1024 KB  

---

### 3️⃣ File Filter
Sirf allowed file types accept karne ke liye.

**Examples:**
- Images → JPG, PNG
- PDF
- Excel
- Word
- Video

---

## ⚙️ Installation

```bash
npm install multer
```

## 📦 Required Modules
```js
const multer = require('multer')
const path = require('path')
```

## 🗂️ Storage Configuration
```js
const storage = multer.diskStorage({
  destination: function (req, file, cb) {
    cb(null, './uploads')
  },
  filename: function (req, file, cb) {
    const newFileName = Date.now() + path.extname(file.originalname)
    cb(null, newFileName)
  }
})
```

## 📝 Example:
- Original file: myPhoto.jpg
- Saved as: 1690000000000.jpg

## 🚫 File Size Limit (5 MB)
```js
const limits = {
  fileSize: 1024 * 1024 * 5 // 5 MB
}
```

## 🚀 Multer Initialization
```js
const upload = multer({
  storage: storage,
  limits: limits
})
```

## 📤 Single File Upload Route
```js
app.post('/submitform', upload.single('imagefile'), (req, res) => {
  res.send(req.file)
})
```

## 📌 imagefile = input field ka name attribute
- 📤 Multiple File Upload (Array)
```js
upload.array('imagefile', 5)
```

## ➡️ Max 5 files upload ho sakti hain
- 📤 Multiple Fields Upload
```js
upload.fields([
  { name: 'profilePic', maxCount: 1 },
  { name: 'documents', maxCount: 3 }
])
```

## 🔐 Express.js – Session (express-session)

### 🔹 Session kya hota hai?
**Session** server-side temporary data hota hai jo **user ke browser (client)** aur **server** ke beech maintain kiya jata hai.  
Isme user se related info temporarily store hoti hai jab tak session valid hai.

📌 Flow:
- Client request bhejta hai → Server
- Server session me data **set** karta hai
- Next request par wahi data **get** hota hai

---

## 🧠 Session ka Use kaha hota hai?

- ✅ User Authentication (Login/Logout)
- 🛒 Shopping Cart
- ⚡ Flash Messages
- 📝 Multi-Step Forms
- ⚙️ User Preferences
- 📄 Form Data Preservation
- 🤖 CAPTCHA Verification

---

## 📦 Installation

```bash
npm install express-session
```

## 📥 Import Package
```js
const session = require('express-session')
```

## ⚙️ Session Middleware Setup
```js
app.use(session({
  secret: 'mysecretkey',
  resave: false,
  saveUninitialized: false,
  cookie: {
    maxAge: 86400000 // 1 day
  }
}))
```

## 🔍 Options Explained:

- secret → session ID ko encrypt/sign karne ke liye
- resave: false → bina change session ko dubara save nahi karega
- saveUninitialized: false → empty session save nahi karega
- cookie.maxAge → session expiry time (milliseconds)

## 📌 Time Calculation:
- 1000 * 60 * 60 * 24 = 1 Day

## 💾 Session Data Store Karna
```js
req.session.key = 'value'
```

## 📝 Example:
```js
req.session.username = 'Abhishek'
```

## 📤 Session Data Read Karna
```js 
res.send(req.session.key)
```

## 📝 Example:
```js
res.send(req.session.username)
```

## ❌ Session Delete / Destroy Karna
```js
req.session.destroy()
```
📌 Mostly logout ke time use hota hai

## ✅ Summary
1. Session server-side data store karta hai
2. express-session middleware required hota hai
3. Session cookies ke through client ko track karta hai
4. Secure & temporary data ke liye best approach hai

## 🔐 Express.js – Authentication (Login System)

### 🔹 Authentication kya hota hai?
**Authentication** ka matlab hota hai user ki **identity verify** karna —  
jaise username & password check karke confirm karna ki user valid hai ya nahi.

---

## 🔁 Authentication Flow (Simple)

1. User **username & password** enter karta hai
2. Request **Express Server** par jaati hai
3. Server:
   - Password ko **bcrypt** se hash/compare karta hai
   - Database (MongoDB via mongoose) se data verify karta hai
4. Agar credentials sahi hain:
   - **Session create** hota hai (`express-session`)
5. User ko authenticated response milta hai

---

## 🧠 Authentication me Use hone wale Tools

- **Express.js** → Server
- **MongoDB + Mongoose** → User data store
- **bcryptjs** → Password hashing & comparison
- **express-session** → Login session maintain karna

---

## 🔑 Password Hashing kya hoti hai?
Plain password ko directly database me store karna **unsafe** hota hai.  
Isliye password ko **hash** karke store kiya jata hai.

📌 Example:
```bash
admin123 → $2b$10$UkHnvuX7lBlmtJkr2QXKN
```

## 📦 bcryptjs Package

### 📥 Installation

```bash
npm install bcryptjs
```
### 📥 Import
```js
const bcrypt = require('bcryptjs')
```

### 🔐 Password Hash Karna
🔹 Async Method (Recommended)
```js
const hashedPassword = await bcrypt.hash(password, 10)
```
🔹 Sync Method
```js
const hashedPassword = bcrypt.hashSync(password, 10)
```
📌 10 = salt rounds (security level)

### 🔍 Password Compare Karna (Login Time)
🔹 Async
```js
const isMatch = await bcrypt.compare('admin123', hashedPassword)
```
🔹 Sync
```js
const isMatch = bcrypt.compareSync('admin123', hashedPassword)
```
➡️ Agar password match hota hai to true return hota hai

### 🧩 Session ke sath Authentication
Login successful hone ke baad:
```js
req.session.userId = user._id
```
Logout ke time:
```js
req.session.destroy()
```
## ✅ Summary
- Authentication user identity verify karta hai
- Password hamesha hashed form me store hota hai
- bcryptjs secure hashing & comparison provide karta hai
- express-session login state maintain karta hai

## 🍪 Express.js – Cookie

### 🔹 Cookie kya hoti hai?
**Cookie** ek chhota sa data hota hai jo **browser (client-side)** me store hota hai  
aur har request ke sath **server** ko automatically send hota hai.

📌 Cookie mostly **temporary information** store karne ke kaam aati hai.

---

## 🔁 Cookie Working Flow

1. Visitor request bhejta hai → Server
2. Server response ke sath **cookie set** karta hai
3. Browser cookie ko store kar leta hai
4. Next request me browser wahi cookie server ko bhej deta hai

---

## 🧠 Cookie ke Use Cases

- ✅ User Authentication
- 🛒 Shopping Cart
- ⚡ Flash Messages
- 🔁 Remember Me / Auto Login
- 🎨 Theme Preferences
- 🌐 Language Selection
- 📝 Form Data Preservation

---

## 📦 Cookie ke liye Required Package

### 📥 Installation

```bash
npm install cookie-parser
```

### 📥 Import
```js
const cookieParser = require('cookie-parser')
```

### ⚙️ Middleware Setup
```js
app.use(cookieParser())
```

### 🔐 Signed Cookies ke liye
```js
app.use(cookieParser('secretkey'))
```
📌 Signed cookies tamper-proof hoti hain

### 💾 Cookie Store Karna
```js
res.cookie('key', 'value', {
  maxAge: 86400000,      // 1 day (1000 * 60 * 60 * 24)
  httpOnly: true,       // JS se access nahi hogi
  secure: true,         // sirf HTTPS par
  sameSite: 'strict',   // 'lax' | 'none'
  signed: true
})
```
🔍 Cookie Options Explained
- maxAge → cookie expiry time (ms)
- httpOnly → XSS attack se protection
- secure → HTTPS only
- sameSite → CSRF protection
- signed → cookie data secure & verified

### 📤 Cookie Read Karna
```js
res.send(req.cookies.key)
```
📌 Signed cookie read karne ke liye:
```js
res.send(req.signedCookies.key)
```

### ❌ Cookie Delete Karna
```js
res.clearCookie('key')
```

### 🔐 Cookie vs Session (Short Difference)
| Cookie                  |	Session                 |
|-------------------------|-------------------------|
| Client-side             | store	Server-side store |

## 🚦 Rate Limiting (API Security)

Rate Limiting ka matlab hota hai **ek fixed time me user / IP se aane wali requests ko limit karna**.

👉 Iska use server ko **overload, brute-force aur DDoS attacks** se bachane ke liye hota hai.

---

### ❌ Problems without Rate Limiting
- Brute-force attacks (login attempts)
- DDoS (Denial of Service)
- Server crash
- Security issues

---

### ✅ How Rate Limiting Works

- Requests **IP Address** ke basis par track hoti hain
- Ek fixed limit hoti hai:
  - Example:  
    - **1 minute → 15 requests**  
    - **10 seconds → 3 requests**
- Limit cross hone par request block ho jaati hai

---

### 🔐 Attacks Prevented
- Brute-force login attacks
- DDoS attacks
- Excessive API misuse

---

## ⚙️ ExpressJS Rate Limiting

### 📦 Common Packages
- `express-rate-limit` → Requests ko limit karne ke liye
- `express-slow-down` → Limit ke baad response slow kar deta hai

---

### 1️⃣ Install Package

```bash
npm install express-rate-limit
```

### 2️⃣ Import Package
```js
const rateLimit = require("express-rate-limit");
```

### 3️⃣ Create Limiter
```js
const limiter = rateLimit({
  windowMs: 15 * 60 * 1000, // 15 minutes
  max: 100, // max 100 requests per IP
  message: "Too many requests from this IP, please try again later."
});
```

### 4️⃣ Apply Limiter to App
```js
app.use(limiter);
```
👉 Ab har IP 15 minutes me max 100 requests hi bhej sakta hai.

### 🧠 Real-Life Example
- Login API → max 5 requests per minute
- OTP API → max 3 requests per minute
- Public API → max 100 requests per 15 minutes

### ⭐ Benefits
- Server stable rehta hai
- Security improve hoti hai
- API misuse control hota hai

```js
const express = require('express');
const puppeteer = require('puppeteer');

const app = express();

app.get('/generate-pdf', async (req, res) => {

  const browser = await puppeteer.launch();
  const page = await browser.newPage();

  const htmlContent = `
    <html>
      <body>
        <h1>Hello PDF!</h1>
        <p>PDF generated using NodeJS & Puppeteer</p>
      </body>
    </html>
  `;

  await page.setContent(htmlContent);

  const pdfBuffer = await page.pdf({
    format: 'A4',
    margin: {
      top: '20px',
      right: '20px',
      bottom: '20px',
      left: '20px'
    }
  });

  await browser.close();

  res.contentType('application/pdf');
  res.send(pdfBuffer);
});

app.listen(3000, () => {
  console.log('Server started on port 3000');
});
```

## 🔌 What is WebSocket?

**WebSocket** ek protocol hai jo **client aur server ke beech persistent (always open) connection** banata hai.

* HTTP → Request–Response (half‑duplex)
* WebSocket → Real‑time, **full‑duplex** communication

---

## 🔁 HTTP vs WebSocket

| Feature       | HTTP        | WebSocket                 |
| ------------- | ----------- | ------------------------- |
| Connection    | Short‑lived | Persistent                |
| Communication | Half‑duplex | Full‑duplex               |
| Real‑time     | ❌           | ✅                         |
| Overhead      | High        | Low                       |
| Use case      | REST APIs   | Chat, Games, Live updates |

---

## 🔄 WebSocket Working (Flow)

1. Client pehle **HTTP request** bhejta hai
2. Server WebSocket handshake accept karta hai
3. Connection upgrade ho jata hai → `ws://`
4. Ab client & server dono **anytime message send/receive** kar sakte hain

---

## 🌐 URL Difference

| Type      | Example                      |
| --------- | ---------------------------- |
| HTTP      | `http://localhost:3000/chat` |
| WebSocket | `ws://localhost:3000/chat`   |

## 🔊 Full‑Duplex Communication

Example: WhatsApp chat

## ✅ Payment Verification Logic

Signature banane ka formula:

```
HMAC_SHA256(order_id + "|" + payment_id, secret_key)
```

### Node.js Verification Code

```js
const crypto = require('crypto');

const generatedSignature = crypto
  .createHmac('sha256', process.env.RAZORPAY_KEY_SECRET)
  .update(order_id + "|" + payment_id)
  .digest('hex');

if (generatedSignature === razorpay_signature) {
  console.log('Payment Verified');
}
```

# NodeJS CRON Job (node-cron)

## 🔹 What is CRON Job?

CRON Job ek **scheduler** hota hai jo kisi task ko **specific time, date ya interval** par automatically run karta hai.

> Simple words:
> 👉 "Jo kaam baar‑baar fixed time par karna ho, uske liye CRON Job use hota hai."

---

## 🔹 When we use CRON Job?

| Use Case           | Explanation                           |
| ------------------ | ------------------------------------- |
| Daily Emails       | Roz users ko email bhejna             |
| Auto Publish Blogs | Scheduled blog posts publish karna    |
| DB Cleanup         | Old database records delete karna     |
| Reports            | Daily / weekly reports generate karna |
| Backup             | Fixed time par data backup            |
| API Fetch          | External APIs se data lana            |
| Security Scan      | Scheduled security checks             |

---

## 🔹 Install & Setup (node-cron)

```bash
npm install node-cron
```

```js
const cron = require('node-cron');
```

---

## 🔹 Basic CRON Job Example

```js
cron.schedule('* * * * *', () => {
  console.log('⏰ This task runs every minute');
});
```

---

## 🔹 CRON Syntax (5 Fields)

```
*  *  *  *  *
|  |  |  |  |
|  |  |  |  └── Day of Week (0 - 6) Sunday = 0
|  |  |  └──── Month (1 - 12)
|  |  └────── Day of Month (1 - 31)
|  └──────── Hour (0 - 23)
└─────────── Minute (0 - 59)
```

---

## 🔹 Common CRON Expressions (With Examples)

| CRON Expression     | Meaning                          |
| ------------------- | -------------------------------- |
| `* * * * *`         | Every minute                     |
| `*/5 * * * *`       | Every 5 minutes                  |
| `0 * * * *`         | Every hour                       |
| `0 */2 * * *`       | Every 2 hours                    |
| `0 9 * * *`         | Everyday at 9 AM                 |
| `0 0 * * *`         | Everyday at 12 AM (midnight)     |
| `0 12 * * *`        | Everyday at 12 PM (noon)         |
| `0 0 * * 0`         | Every Sunday at midnight         |
| `0 0 1 * *`         | 1st day of every month           |
| `0 0 15 * *`        | 15th of every month              |
| `*/30 9-17 * * 1-5` | Every 30 mins (9AM‑5PM, Mon‑Fri) |

---

## 🔹 Real‑World Example: Daily Email Sender

```js
cron.schedule('0 9 * * *', () => {
  console.log('📧 Sending daily emails at 9 AM');
});
```

---

## 🔹 Important Interview Points

* CRON jobs are **time‑based schedulers**
* node-cron is used in **NodeJS applications**
* Runs tasks in **background**
* Not recommended for **heavy CPU tasks**
* In production, ensure **single instance execution**

---

## 🔹 CRON Job vs setInterval

| CRON Job           | setInterval         |
| ------------------ | ------------------- |
| Time‑based         | Interval‑based      |
| Production ready   | Not reliable        |
| Supports schedules | No calendar support |

---

## 🔹 Common Mistakes

❌ Forgetting timezone
❌ Running CRON in multiple server instances
❌ Using CRON for heavy tasks
